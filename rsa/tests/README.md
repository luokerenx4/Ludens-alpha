# 外部测试

RSA 在这里集中维护自身测试及依赖的行为契约。OMP 专项测试从公开 provider API 调用已安装的固定版本，测试源码与 fixture 留在本仓库，不放进 OMP 源码树或依赖补丁。更换 Shiori 实现时可以单独迁移这些契约，不把当前实现细节当作 Harness 通用接口。

## Codex WS 恢复专项 · 2026-10-20

**这是架构施工期明确采用的一次 TDD 特例，不是全项目必须先写测试的开发规则。** 历次长运行暴露了相邻故障分支的遗漏，因此本次先构造外部故障工况、确认旧实现失败，再修改恢复策略。后续改架构时按契约重新判断用例价值，不为保留测试而保留旧架构。

入口：[omp-websocket.test.ts](omp-websocket.test.ts)。在 `rsa/` 中运行：

```sh
bun run test:transport
bun run check
# 带标准事件和检查证据的两个真实故障族，可由现有看板读取：
bin/rsa bench run ws-recovery
```

### 构建依据

- **实跑 R1：** 2026-10-18 Besiege 六小时运行，收到 `websocket_connection_limit_reached`，此前有空 thinking 占位。先前补丁已覆盖到期后恢复。
- **实跑 R2：** 马里奥制造八小时运行，run ID `2026-10-19T13-19-53.903Z`。北京时间 23:19:59 到期，23:21 恢复 WS；23:46:56 收到 `websocket closed (1012)`，此后约 5.5 小时保持 SSE。证明缺口在另一类连接关闭的恢复分类，不能据此确定实际服务端或网络故障来源。
- **扩展 S：** 其余关闭码、握手阶段、输出交付边界、尺寸和取消均为合成邻近工况，不声称它们在 R2 中实际发生。关闭码名称参考 [IANA WebSocket Close Code Registry](https://www.iana.org/assignments/websocket/websocket.xhtml#close-code-number)；恢复策略是本项目的选择，不是协议强制行为。

### 环境与观测范围

使用 Bun 1.4、固定并应用本地补丁的 `@oh-my-pi/pi-ai@18.9.1`，调用真实 `streamOpenAICodexResponses`，每例创建独立 provider session。WS 和 HTTP 完全由进程内 fixture 替换，鉴权是合成 token，不读取本机登录、不调用在线模型、不连接模拟器。

`Date.now` 虚拟推进 60 秒冷却；握手 watchdog 加速到 0ms；重试 backoff 使用受控 scheduler，首事件超时使用 1ms watchdog。断言关注请求次数、状态、交付事件和真实序列化请求体，耗时不代表网络或服务端性能。测试使用全局传输替身，应顺序执行；finally 恢复环境并关闭会话。

### 工况矩阵

| 工况 | 来源 / 注入位置 | 必须观察到的行为 |
| --- | --- | --- |
| 正常首帧、增量、连接替换 | S，正常完成后旧 socket 关闭 | 新连接完整历史、无旧 `previous_response_id`，下一轮恢复 delta |
| 连接到期 | R1/R2，空 thinking 后 error event | 当前请求安全回退 SSE；60 秒内不握手；随后全历史 WS → delta |
| 中途关闭 1000/1001/1006/1011/1012/1013 | R2 的 1012 + S，空 thinking 后 close | 同一临时恢复策略，不能永久禁用整个会话的 WS |
| 握手关闭 1006/1012/1013、握手超时 | S，连接尚未打开 | 当前请求 SSE、冷却内无新握手、冷却后新连接 |
| 协议/数据/策略拒绝 1002/1003/1007/1008/1010 | S，握手关闭 | 保持会话 WS 禁用；时间过去或压缩都不自动解除 |
| send 抛错、损坏 JSON、首事件超时 | S，尚无内容交付 | 有界重试，耗尽后 SSE 冷却；下一次正常请求可恢复，无密集无限重连 |
| 已交付 text/thinking/tool 后到期或 1012 | S，分别在输出交付后注入 | 当前请求返回 error，已交付内容只出现一次；后续仍有冷却和 WS 恢复机会 |
| 本地 UTF-8 帧 >15MiB、远端 1009 | 既有尺寸回归 + S | 完整 SSE；尺寸阻断时不反复握手；仅原生压缩解除尺寸阻断 |
| 累计历史 >15MiB、实际 delta 很小 | S | 按实际发送帧判断，正常继续增量 WS |
| 已交付工具后 1009 | S | 工具不重放，仍记录尺寸阻断；后续 SSE，压缩后 WS |
| 人工/预算取消：握手中、部分输出后、拒绝同时取消 | S | aborted、不发额外 SSE、不污染后续请求的传输选择 |

恢复分类与当前响应能否重放分开：暂时断连统一冷却；尺寸问题等原生压缩；明确协议、数据、扩展或策略拒绝保持禁用。关闭码从原生 close event 传入错误对象，恢复分类不匹配错误字符串。1002/1003/1007/1008/1010 之外，注册的鉴权拒绝 3000/3003 采用同样禁用策略；未覆盖的私有关闭码不推断业务含义，按暂时传输故障冷却。

### 红绿记录与边界

2026-10-20，修补前的扩展专项为 **19 通过 / 18 失败**：包括关闭后长期 SSE、握手关闭分类、部分输出重放及未记录后续恢复。`ws-recovery` v2 的到期族通过，1012 族的冷却与恢复失败。随后追加空 thinking 占位开始/结束配对断言，旧行为另有 7 项失败；复用 OMP 的块关闭方法补齐。最终专项 **37 通过 / 515 断言**，两类看板基准均通过；RSA 全套 **154 通过、3 个真实设备测试跳过、0 失败**。后续结果以当前命令输出为准。

这组测试证明受控工况下的行为，不证明在线服务从不掉线，也不证明实际重连耗时。真实长跑、调度和吞吐仍看运行日志。256k 压缩阈值、模型设置、游戏策略不属于本次变更。

看板基准在 [src/benchmark/cases/ws-recovery.ts](../src/benchmark/cases/ws-recovery.ts)，只复现两类实际事件并输出 `benchmark_fault` 的来源和模拟条件；更宽的边界矩阵集中在本目录。升级 OMP 时先运行专项，再运行基准，无需向依赖中拷贝测试。
