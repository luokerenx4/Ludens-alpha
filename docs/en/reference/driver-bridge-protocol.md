# Driver Bridge Protocol

This spec defines the Baseware `bridge` transport layer (TCP socket) emulator communication protocol, implemented jointly by the optional standalone packages [mgba](https://github.com/luokerenx4/ludens-gba-driver), [azahar](https://github.com/luokerenx4/ludens-3ds-driver), and [ryubing](https://github.com/luokerenx4/ludens-switch-driver). When developing a new emulator driver, implement the Bridge server side of this protocol on the emulator side, and provide a matching Provider on the TypeScript side via `DriverRegistration.load` (for the package registration contract see [Baseware Philosophy and Capability Contracts](baseware.md#driver-packages-and-launch-description)). Note: the `cua` desktop driver uses `stdio` MCP transport and does not use this protocol.

## Transport

- **Connection model**: TCP `127.0.0.1:<port>`, exclusive single client. The Baseware Provider acts as client initiating the connection; the emulator-side Bridge acts as server listening.
- **Frame format**: tab (`\t`)-separated line protocol delimited by UTF-8 newlines (`\n`):
  - Request line: `{id}\t{op}\t{args...}\n`
  - Success response: `{id}\tOK\t{fields...}\n`
  - Failure response: `{id}\tERROR\t{message}\n`
- **Async request pairing**: `id` is generated by the Provider (`crypto.randomUUID()`); the Bridge must echo it verbatim at the head of the response line. Requests are paired precisely by `id`; `APPLY` and operations that must wait for device sampling or rendering respond lazily — see each instruction for timing.
- **Character escaping constraint**: no field may contain `\t`, `\r`, or `\n` (enforced by [baseware/src/drivers/bridge.ts](../../baseware/src/drivers/bridge.ts)). A dropped TCP connection counts as device disconnect and immediately fires the Provider's `onDisconnect` callback.

## Sessions and Ownership

| Instruction (`op`) | Request Params | Response Format | Semantics |
| --- | --- | --- | --- |
| `HELLO` | none | `OK\t<version...>` | Connection handshake and version check. `mgba` returns `<frequency>\t<cycles>` (used to compute the exact frame rate); `azahar` must return `azahar-rsa-3`; `ryubing` must return `ryubing-rsa-3`. The Provider closes the connection immediately on version mismatch. |
| `OWN` | `<epoch>` | `OK` or `ERROR OWNED` | Requests device control. Rejected if a holder already exists, including a repeat with the same epoch (`mgba` returns `ALREADY_OWNED`, `azahar` / `ryubing` return `OWNED`); the Provider handles same-epoch idempotency one layer up. Gamepad input state is zeroed immediately after a successful takeover. |
| `DISOWN` | `<epoch>` | `OK` or `ERROR STALE_EPOCH` | Releases device control. In-flight gamepad actions settle as `interrupted` and keys are zeroed; `azahar` and `ryubing` also release touchscreen contacts. |
| `STATE` | `<epoch>` | see below | Reads the control state currently held by the Bridge injection layer (reflects controller state only; never reads game memory). |

Per-emulator `STATE` response field formats:

- **mGBA**: `OK\t<mask>\t<actionId|->\t<nativeKeys>` (`mask` is the 10-bit GBA button bitmap; `nativeKeys` is the `emu:getKeys()` native diagnostic value).
- **Azahar / Ryubing**: `OK\t<mask>\t<lx>\t<ly>\t<rx>\t<ry>\t<actionId|->` (`mask` encodes buttons in each Provider's `BUTTONS` bit order; left/right stick axes `lx/ly/rx/ry` are `[-32767, 32767]` integers, normalized Provider-side to `[-1, 1]` by dividing by `32767`).

Except for `OWN`, any instruction carrying `<epoch>` that does not match the Bridge's current owner returns `ERROR STALE_EPOCH`.

## Pad Timeline

| Instruction (`op`) | Request Params | Response Format | Semantics |
| --- | --- | --- | --- |
| `APPLY` | `<epoch>\t<sequence>` | Deferred response: `OK\t<outcome>\t<timing...>` (fields below) | Executes a compiled gamepad-state sequence; `outcome` is `completed` or `interrupted`. Returns `ERROR BUSY` if an action is already in flight. |
| `STOP` | `<epoch>\t[actionId]` | `OK` | If `actionId` is omitted or matches the current in-flight action, interrupts it immediately (settling `APPLY` as `interrupted`) and zeroes inputs; `azahar` / `ryubing` release the touchscreen under the same rules. |

`APPLY` terminal timing fields differ per device: mGBA returns `<startFrame>\t<endFrame>`; Azahar / Ryubing return `<elapsedMs>\t<polls>`. The Provider keeps emulated-frame counts or wall-clock elapsed time and sample counts accordingly, never treating frame numbers as milliseconds.

Provider-side, [timeline.ts](../../baseware/src/drivers/timeline.ts) `compileTimeline` first validates the multi-channel `pad.play` inputs and slices them into non-overlapping full-state spans, then encodes them as a comma-separated `<sequence>` string:

- **mGBA (frame-driven)**: each span is `mask:frames` (`mask <= 1023`, `frames >= 1`). The Provider converts milliseconds to emulated frames with cumulative `ceil(elapsedMs * fps / 1000)` rounding.
- **Azahar / Ryubing (poll wall-clock driven)**: each span is `mask:lx:ly:rx:ry:durationMs` (`azahar` `mask < (1 << 14)`, `ryubing` `mask <= 65535`, stick axes `|v| <= 32767`, `durationMs >= 16`). Advances on the monotonic wall clock at emulator input-poll points, each span lasting at least 16ms.

## Touch

Only `azahar` and `ryubing` support touchscreen instructions (`mgba` has no touch hardware):

| Instruction (`op`) | Request Params | Response Format | Semantics |
| --- | --- | --- | --- |
| `TOUCH_INFO` | none | `OK\t<minX>\t<minY>\t<maxX>\t<maxY>` | Queries native touchscreen coordinate bounds. `azahar` returns `0 0 319 239`, `ryubing` returns `0 0 1279 719`. The Provider generates JSON Schema from this and rejects out-of-bounds coordinates. |
| `TOUCH_DOWN` | `<epoch>\t<x>\t<y>` | Deferred response: `OK\tcompleted` or `OK\tinterrupted` | Presses at the given coordinates; returns `completed` once the emulator completes one input sample, with contact held after the return. Returns `ALREADY_DOWN` / `TOUCH_ALREADY_DOWN` if already pressed. |
| `TOUCH_MOVE` | `<epoch>\t<x>\t<y>` | Deferred response: `OK\tcompleted` or `OK\tinterrupted` | Moves the current touch point; returns `completed` after sampling. Returns `NOT_DOWN` / `TOUCH_NOT_DOWN` if not currently pressed. |
| `TOUCH_UP` | `<epoch>` | Deferred response: `OK\tcompleted` or `OK\tinterrupted` | Lifts the touch point and waits for one input sample; returns `interrupted` if cancelled or control is handed over while waiting. Returns `completed` idempotently when not pressed with no touch request in flight. |

At most one touch request may be in flight at a time; concurrent requests return `BUSY` / `TOUCH_BUSY`. When the caller cancels a request (`AbortSignal` fires `STOP <epoch> <touchId>`), calls `pad.release`, or executes `DISOWN`, the Bridge immediately lifts the touch contact.

## Capture

| Emulator | Request Format | Deferred Response Format | Timing and Constraints |
| --- | --- | --- | --- |
| `mgba` | `CAPTURE\t<path>` | `OK\t<frame>` | Synchronously captures the current frame into `<path>` and returns the current emulated frame number. |
| `azahar` | `CAPTURE\t<top\|bottom>\t<path>` | `OK\t<captureSequence>` | Captures the top screen (400×240 left eye) or bottom screen (320×240) into the absolute path `<path>` and returns an incrementing capture sequence number. Both screens share one native capture slot, sampled serially. |
| `ryubing` | `CAPTURE\t<path>` | `OK\t[frame]\t<surface>` | Captures at the next render-frame present callback (15s timeout); `<surface>` indicates game frame vs. system keyboard popup (`frame` is omitted for system keyboard popups). |

Image bytes never travel over the TCP socket: the Provider allocates a local temp file path via `withCaptureFile` in [capture.ts](../../baseware/src/drivers/capture.ts) and passes it to the Bridge; after `CAPTURE` returns `OK` it reads the file bytes and deletes the temp file immediately in `finally`.

## Keyboard

Only `ryubing` supports native system-keyboard instructions:

- Request format: `KEYBOARD\t<epoch>\t<type|press>\t<base64Payload>`
- Response format: `OK` or `ERROR NO_TEXT_INPUT`
- Semantics: only takes effect while the Switch system text-input box is in the foreground and active; `type` inserts the Base64-decoded UTF-8 text, `press` supports the four control keys `ENTER`, `ESCAPE`, `BACKSPACE`, `CTRL+A`.

## Error Code Reference

| Error Code | Meaning and Trigger |
| --- | --- |
| `STALE_EPOCH` | The request's `epoch` does not match the Bridge's current owner, or `OWN` has not happened yet. |
| `OWNED` / `ALREADY_OWNED` | The device is already held by a control cycle; repeat `OWN` is refused (including the same epoch). |
| `BUSY` | An unfinished `APPLY` gamepad timeline is already in flight. |
| `CAPTURE_BUSY` | An unfinished capture request is already in flight. |
| `TOUCH_BUSY` / `ALREADY_DOWN` / `NOT_DOWN` | Touchscreen state-machine conflicts (concurrent touch, repeated press, or move while not pressed). |
| `NO_GAME` / `PAUSED` / `NO_RENDERER` / `CAPTURE_SAVE_FAILED` | Emulator has no game loaded, is paused, the renderer is not ready, or the temp capture write failed. |
| `NO_TEXT_INPUT` | Ryubing currently shows no visible system keyboard input box. |
| `UNKNOWN_COMMAND` | Unknown operation instruction. |

The Provider converts all `ERROR` responses into structured exceptions; `OK\tinterrupted` caused by `STOP` or `DISOWN` is handled as a normal interrupted terminal state (maps to `ExecutionResult.status = "interrupted"`, `exitCode = 130`).

## Provider/Bridge Split

- **Provider (TypeScript side) owns**: JSON Schema generation and parameter boundary validation, `pad.play` multi-channel timeline compilation and span encoding, control-lease holder bookkeeping, temp capture-file allocation and cleanup.
- **Bridge (emulator native side) owns**: injecting buttons and touch at the correct hardware moments (input-poll points / emulation frame boundaries / render present callbacks), framebuffer capture, maintaining the low-level `epoch / action / touch` state machine, and unconditionally zeroing inputs on disconnect or `DISOWN`.
