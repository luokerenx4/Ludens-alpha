# Dashboard UI

The Dashboard uses the Next.js App Router, React, Tailwind CSS 4, and shadcn/ui (Radix / New York). The web page and the optional Electron desktop client share the same components; you do not need to start Electron to develop the UI.

## Component Ownership

- `rsa-dashboard/components/ui/` holds component sources introduced via the official shadcn CLI. Buttons, forms, switches, checkboxes, radio groups, sliders, cards, tables, dialogs, feedback, and in-page tabs should reuse these primitives.
- shadcn/ui sources are under the MIT License; the license text is kept in [`licenses/shadcn-ui.txt`](../../../licenses/shadcn-ui.txt).
- Feature components still live in `components/`; the run timeline, activity evidence, charts, and pet animations are implemented by feature components — never add workspace or RSA calls into the UI primitives.
- Class-name merging uses `import { cn } from "cn"`, variants use `class-variance-authority`; both stay consistent with the sources generated by the current shadcn registry.

`components.json` records the registry style and paths. To add a new component, run it from the Dashboard directory, for example:

```bash
cd rsa-dashboard
npx shadcn@4.23.0 add dialog
```

Only add components currently in use. After generation, review the sources and lockfile; do not use `--overwrite` to clobber local modifications. Current local adjustments include `NativeSelect.wrapperClassName` (controls the wrapper width) and the Slider passing the accessible name and description through to the actually focusable Thumb. Cards use compact defaults (20px padding, 16px section gaps, and 13px descriptions) suited to the console.

## Theming and Styling

`app/globals.css` imports Tailwind and `tw-animate-css`, mapping the existing Ludens dark palette onto semantic tokens via `@theme inline`. The root layout is pinned to `dark`; there is currently no theme-switching feature.

| Purpose | Recommended classes |
| --- | --- |
| Page and primary text | `bg-background text-foreground` |
| Cards and overlays | `bg-card` / `bg-popover` |
| Primary action | Button default variant, using the `primary` gold |
| Secondary actions and weak backgrounds | Button `secondary` / `outline` / `ghost`; `bg-muted` |
| Descriptions and status | `text-muted-foreground` / `text-success` / `text-destructive` |
| Borders, keyboard focus | `border-border` / `ring-ring` |

Note that `--muted` denotes a weak background, while text uses `--muted-foreground`. Existing domain CSS lives in `@layer components`, allowing the Tailwind `utilities` layer to override it; do not add new unlayered global `button` / `input` / `select` styles, or they will override the shared controls' state, size, and focus styles.

Workspace management, settings, Benchmark, Capabilities, Docs, Activity Feed, request details, replay controls, and Loop Lab use the shared primitives. Keep domain geometry (timeline marks, charts, evidence rows, and media) in feature CSS; use theme tokens for surrounding surfaces and status colors.

The visual baseline is a warm charcoal canvas with restrained gold actions, quiet borders, and consistent card spacing. Global settings use two columns from 1180px and one column below that width. Keep related controls together, allow translated labels to wrap, and verify real English and Chinese pages at desktop and narrow widths when adapting a generated design concept.

Workspace entry uses a searchable library with creation, existing-folder registration, and default-location changes in separate dialogs. Keep advanced fields behind disclosure, derive community-driver fields from the verified manifest, and show a final location preview. Completing a write must remain successful even if later catalog refreshes fail; use the returned identity for confirmation and navigation.

Workspace selection belongs in the shared top context bar. Settings stays in the sidebar footer below the optional pet panel; on narrow screens, navigation is disclosed from a menu so it does not push the workspace context below the fold.

The Benchmark catalog uses that same workspace context. Changing workspaces clears the previous task, result and pagination selection. The selected history filter is independent of the task belonging to the displayed result.

Live distinguishes the selected evidence, automatic page refresh, and the last observed host state. The global **Return to latest** action clears historical context and activity filters, then reads observations and logs together. **Latest logs** only updates the current log scope and filter. Pausing automatic refresh preserves the viewed workspace/run; intentional navigation and explicit refresh actions still read a snapshot without resuming polling.

Documentation follows the interface language unless `docLang=en` or `docLang=zh` explicitly selects one. The document index and article use the same language preference, with a visible fallback notice when a translation is missing. Native document links preserve workspace context and explicit language in ordinary clicks and new tabs. Search filters titles and paths; article heading links store their destination in `docAnchor` for deep links and browser history. Desktop reading uses separate document and heading navigation; narrow screens disclose both through the sticky document toolbar. Code copying uses the renderer's source text, preserving indentation and internal blank lines.

Docs, Capabilities, and Perception expose explicit retries for failed reads. A failed refresh keeps the last loaded content; driver verification and unsaved perception edits stay separate from GET state. Workspace catalog failures are shown as errors, never as an empty workspace list. Retrying a read never replays a write, and a successful perception save supersedes any earlier read.

Replay separates playback sampling from event inspection. Playback loads bounded 30-second frame windows; the frame API accepts at most 60 seconds per request. Event windows can cover up to 15 minutes without expanding the frame window. Precise elapsed-time entry, ten-second jumps, and the seek bar move within the selected run or cycle. Missing samples and recording gaps remain visible; a later frame must never be shown as evidence for an earlier time.

Replay event search reads the entire selected run or cycle through the server's existing archive index. It matches literal, case-insensitive titles, statuses, event types, and identifiers, with an optional track filter; it does not search arbitrary payloads or expand artifacts. Each response scans at most 500 event candidates and returns at most 100 matches. The interface continues through empty scan pages automatically, permits cancellation and retry, and keeps displayed result batches bounded. Cursors bind the query and scope to a source generation and fixed event snapshot: appended events require a fresh search, while rewritten sources invalidate old cursors. Finishing that snapshot is distinct from indexing the whole archive; only both `scan.complete` and `coverage.complete` justify an exhaustive result or a definitive empty state.

Replay evidence links preserve workspace, run, cycle, and time together with `replayItem`, or `replayRecord` plus `replaySequence`. Native links support new tabs and browser history. Details show recorded identifiers, times, status, source text, and exact model inputs where recorded; missing input media is not replaced with a nearby screenshot. Truncated text is labelled and the full record remains available in the raw-data disclosure. Invalid or unavailable references stay explicit. Seeking, searching, copying links, reading details, and retrying reads never start a driver, model, or game or change host control.

## Interaction Conventions

- Associate form controls with a `Label`, and help text via `aria-describedby`. Icon buttons must have an accessible name.
- Dialogs must have a title and description, focus the first useful input, restore focus to the opener on cancel, and focus the result after a successful creation. Keep in-progress creation visible instead of allowing an accidental dismissal.
- Give buttons an explicit `type`; use `submit` for the submit button of a native form and `button` for everything else.
- `NativeSelect` keeps native option, empty-value, and keyboard behavior; use `Switch` for discrete toggles and `Slider` for numeric ranges.
- Request-detail tabs use the shared `Tabs` primitive for Arrow, Home, and End navigation; inactive panels remain unmounted.
- Whole-row evidence and timeline hit targets may keep native buttons with explicit types and visible keyboard focus. The replay seek bar keeps its native range to preserve continuous millisecond seeking and URL commits on pointer/key release; hidden sound-file inputs remain native.
- Sliders with backend writes update the local value on `onValueChange` and persist on `onValueCommit`, avoiding request storms while dragging.
- Feature requests, pending states, error feedback, and desktop-capability detection are owned by the page; UI primitives handle only presentation and interaction.

Acceptance uses `npm run typecheck`, `npm test`, and `npm run build`, plus checking pages and form actions under an isolated `LUDENS_HOME`. See [Console Debugging and Verification](../tutorials/debugging-and-verification.md).
