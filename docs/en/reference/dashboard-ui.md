# Dashboard UI

The Dashboard uses the Next.js App Router, React, Tailwind CSS 4, and shadcn/ui (Radix / New York). The web page and the optional Electron desktop client share the same components; you do not need to start Electron to develop the UI.

## Component Ownership

- `rsa-dashboard/components/ui/` holds component sources introduced via the official shadcn CLI. Buttons, forms, switches, checkboxes, radio groups, sliders, cards, tables, dialogs, feedback, and in-page tabs should reuse these primitives.
- shadcn/ui sources are under the MIT License; the license text is kept in [`licenses/shadcn-ui.txt`](../../../licenses/shadcn-ui.txt).
- Feature components still live in `components/`; the run timeline, activity evidence, charts, and pet animations are implemented by feature components — never add workspace or RSA calls into the UI primitives.
- Class-name merging uses `import { cn } from "cn"`, variants use `class-variance-authority`; both stay consistent with the sources generated by the current shadcn registry.

`components.json` records the registry style and paths. To add a new component, run it from the Dashboard directory, for example:

```bash
cd rsa-dashboard
npx shadcn@4.23.0 add dialog
```

Only add components currently in use. After generation, review the sources and lockfile; do not use `--overwrite` to clobber local modifications. Current local adjustments include `NativeSelect.wrapperClassName` (controls the wrapper width) and the Slider passing the accessible name and description through to the actually focusable Thumb. Cards use compact defaults (20px padding, 16px section gaps, and 13px descriptions) suited to the console.

## Theming and Styling

`app/globals.css` imports Tailwind and `tw-animate-css`, mapping the existing Ludens dark palette onto semantic tokens via `@theme inline`. The root layout is pinned to `dark`; there is currently no theme-switching feature.

| Purpose | Recommended classes |
| --- | --- |
| Page and primary text | `bg-background text-foreground` |
| Cards and overlays | `bg-card` / `bg-popover` |
| Primary action | Button default variant, using the `primary` gold |
| Secondary actions and weak backgrounds | Button `secondary` / `outline` / `ghost`; `bg-muted` |
| Descriptions and status | `text-muted-foreground` / `text-success` / `text-destructive` |
| Borders, keyboard focus | `border-border` / `ring-ring` |

Note that `--muted` denotes a weak background, while text uses `--muted-foreground`. Existing domain CSS lives in `@layer components`, allowing the Tailwind `utilities` layer to override it; do not add new unlayered global `button` / `input` / `select` styles, or they will override the shared controls' state, size, and focus styles.

Workspace management, settings, Benchmark, Capabilities, Docs, Activity Feed, request details, replay controls, and Loop Lab use the shared primitives. Keep domain geometry (timeline marks, charts, evidence rows, and media) in feature CSS; use theme tokens for surrounding surfaces and status colors.

The visual baseline is a warm charcoal canvas with restrained gold actions, quiet borders, and consistent card spacing. Settings puts console preferences first. Pet following separates the saved workspace from the observed desktop state. This window’s optional desktop controls have their own availability section, and desktop preference cards use two columns from 1100px; narrower screens use one column. Keep related controls together, allow translated labels to wrap, and verify real English and Chinese pages at desktop and narrow widths when adapting a generated design concept.

Run analysis puts request inspection before aggregate performance. Desktop uses a request list beside its detail pane; narrow screens use a labelled request chooser with older/newer controls and the detail directly below. Metrics and trend charts remain in a secondary disclosure. Charts explain missing measurements instead of showing empty axes; recorded zero values, wait-only latency and gaps remain meaningful.

Selecting another request on the same workspace path, run, cycle and page preserves the request controls while its details load. Details belong only to the exact requested read and request ID; pending, failed and missing selections must not display the previous request as the new one. Read failures expose an explicit retry, successful retries restore focus only if the user has not moved it elsewhere, and changing workspace, run, cycle or page cannot retain a different scope's content.

Workspace entry uses a searchable library with creation, existing-folder registration, and default-location changes in separate dialogs. Keep advanced fields behind disclosure, derive community-driver fields from the verified manifest, and show a final location preview. Completing a write must remain successful even if later catalog refreshes fail; use the returned identity for confirmation and navigation.

Default-location updates return the committed `{ config }`; removals return `{ removed }`, containing the actual registration removed under lock or `null` when it was already absent. The UI applies these receipts before independently refreshing the catalog; read retries do not repeat writes. Undo uses the returned path, never a stale list row. Before unregistering, the shared CLI/Dashboard operation clears only a pet target pointing to that workspace. If target cleanup fails, the registration remains and the user can retry explicitly after fixing the problem. A successful removal never resumes following when the directory is registered again.

Workspace selection belongs in the shared top context bar. On desktop, navigation and the optional pet panel share one scrolling middle region, while Settings stays in its own bottom-left footer. Short windows and long pet status messages must not shrink navigation out of reach; keyboard focus scrolls each reached link or action into view. At 680px and below, the menu discloses navigation, the pet panel and Settings in normal page flow. Crossing that breakpoint moves focus only when its current sidebar control becomes hidden.

Settings works in the browser without Electron. Language appears first and workspace following remains available through the server. The optional desktop section checks only this window’s bridge, explicitly and on focus/visibility changes; it never launches the desktop app or treats the server consumer’s connection as a local bridge. Unknown visibility, sound, and notification values stay unknown until read, rather than appearing as disabled defaults. Failed reads retain labelled cached values and expose a read-only retry. A write that cannot be confirmed is never replayed; read the settings again before making another change. Bridge lifetimes, operation identities, and newer subscription values guard reads, writes, file validation, and sound preview against late results after replacement or disconnect.

The pet follow selector saves immediately and keeps focus while saving. A target PUT returns the exact committed `{ target }`; a consumer heartbeat POST returns `{ consumer }`. Neither receipt depends on a subsequent read. The UI applies the target receipt before separately reading desktop status. A failed consumer read retains the target and reports unknown connection state; a failed full read keeps the labelled saved or cached selection. A missing write response remains unconfirmed, retains the requested and last confirmed choices, and blocks further changes until an explicit read succeeds. Recovery never repeats the write. Paths and raw errors are disclosed on demand. Saved selection, desktop connection and application are separate facts: `targetRevision` identifies the attempted selection while `revision` identifies the loaded source, so an old error cannot be attributed to a new choice. An offline or unregistered saved target remains visible with `targetUnavailable`; the desktop stops consuming it without clearing the saved choice and can reconnect when it becomes available. Before the first saved choice, the selector shows an unset placeholder. Choosing **Stop following** explicitly saves `null`, so a later `ifUnset` launch cannot select a workspace automatically.

Perception uses exact numeric inputs with presets, optional sliders, and explicit override/inheritance sources. Drafts are isolated by workspace identity and registered path and retained in the current tab; saving, re-reading, and checking the running process are separate operations. Only a current scoped host observation can supply running values, and inherited provenance is not inferred. The copyable reload command includes the workspace and removes an inherited socket override; the page never executes it. See [Perception configuration and recovery](../tutorials/perception-and-action.md).

The inheritance rule appears once above the fields. Each field keeps its purpose and source selector, with its own labelled built-in default when inheritance is selected. These defaults are fallback values, not evidence of the running process. Saved settings and running observations remain separate sections; they sit alongside each other on wide screens and stack on narrower screens, retaining read and recovery actions.

Capabilities presents evaluation tasks as one semantic list: aligned columns on wide screens and full-width stacked entries on phones. Each entry keeps its name and description together, discloses the complete content digest on demand, and links to the exact task in Benchmark using the current workspace, name and digest. Resizing keeps the same controls and expanded state. The capability response does not contain a declared task version; read that in the exact-task Benchmark panel instead. Task source status, diagnostics, cached-read labels and the general Benchmark entry remain independent of these links.

The Benchmark catalog uses that same workspace context. Changing workspaces clears the previous task, result and pagination selection. The selected history filter is independent of the task belonging to the displayed result.

Execution history keeps each run's time, task, execution status, full score-version ID and actions in one entry. Wide screens align the fields in columns; narrow screens stack them so setting a baseline or opening the original run does not move its identity out of view. The same controls remain in the DOM across widths. Selecting a result and selecting its comparison baseline retain their exact run and score-version references independently; missing scoring stays explicitly unscored.

At 900px and below, a labelled task chooser replaces the desktop task rail so the selected package appears immediately below it. Choices use the complete task name and digest; missing or ambiguous references stay explicit. **All execution history** clears only the task filter and history page, preserving an independently selected result or baseline. **View execution history** moves to the history region without running an evaluation. Retained same-workspace task metadata stays labelled during pending or failed history reads; another workspace path cannot inherit it. Resizing transfers focus only when the currently focused task control becomes hidden.

Loop Lab is a local mathematical simulation, independent of workspace settings and actual runs. Choose a delivery scenario, then expand **Adjust simulation** to edit raw parameter drafts and apply them together. Empty, non-finite, out-of-range and fractional count values show field errors without changing the previous estimates. **Reset parameters** restores numerical defaults without changing layers. Layer switches update the estimates immediately using the applied parameters; an unmatched combination is labelled **Custom layers**, with no preset falsely selected. The same applied parameters are used for all comparison scenarios, including explicit observe in a single-round scenario. Drafts, applied parameters, layers and request selection survive navigation and language changes in the current tab; a browser reload starts a new lab session.

On narrow screens, controls start collapsed so estimated results and the chart appear first. Exact request input, previous/next controls and the slider offer the same selection as the graph. The SVG chart resizes without shrinking its height, marks compaction before the affected request, and reports the history compaction threshold separately from request totals. **Delivered frame tokens** count every successfully delivered frame payload, exclude state notices and do not decrease after compaction; **Retained perception tokens** include remaining perception text, images and state notices. Request breakdowns show actual values from the simulation. Loop anatomy and recent simulated history are secondary disclosures. No lab interaction starts a model or changes a real run.

Live distinguishes the selected evidence, automatic page refresh, and the last observed host state. The global **Return to latest** action clears historical context and activity filters, then reads observations and logs together. **Latest logs** only updates the current log scope and filter. Pausing automatic refresh preserves the viewed workspace/run; intentional navigation and explicit refresh actions still read a snapshot without resuming polling.

Live places the observation and activity before secondary metrics. **Run details** contains model, budget and performance data; **Perception & record details** contains process, query and timeline data. These sections start collapsed, while query or delivery failures remain visible above the observation. A single model-input image is not repeated as a thumbnail; multiple input images remain selectable in an expandable strip. Text, audio and missing-media states use their content height. Failed recorded images and text have an explicit same-resource read retry; audio retry rechecks availability and restores the controls without starting playback. Retries preserve the current scope and automatic-refresh setting and never execute perception or change host control.

Activity entries use the full reading width on narrow screens, with source/type/status in a compact header and a separate copy action. Copy uses the complete recorded block text, even while its preview is collapsed. Long content can be expanded for keyboard reading; a shorter replacement remains visible. Copy success or failure is announced without changing the selected block. **Source & links** preserves the complete recorded source and trace fields, event sequence and block identifier on demand.

Documentation follows the interface language unless `docLang=en` or `docLang=zh` explicitly selects one. The document index and article use the same language preference, with a visible fallback notice when a translation is missing. Native document links preserve workspace context and explicit language in ordinary clicks and new tabs. Search filters titles and paths; article heading links store their destination in `docAnchor` for deep links and browser history. Desktop reading uses separate document and heading navigation; narrow screens disclose both through the sticky document toolbar. Code copying uses the renderer's source text, preserving indentation and internal blank lines.

The document library switches to **Docs menu** at 900px and below; heading navigation switches to **On this page** at 1300px and below. Each sidebar and its replacement share the same inclusive breakpoint. When resizing hides a focused navigation control, focus moves to its visible counterpart. An open menu stays open while resizing; dismissing it returns focus to its visible trigger or the corresponding sidebar. Selecting a document or heading still focuses the reading destination, and resizing does not change the search draft, workspace, or language.

Navigation menus keep their title and single Close control outside the scrolling body. Descriptions, full document titles, search and directory links scroll inside that body, leaving the header compact even in short windows. Keyboard navigation scrolls reached entries into view; wrapping from the last item keeps Close visible without scrolling the whole dialog.

Docs, Capabilities, and Perception expose explicit retries for failed reads. A failed refresh keeps the last loaded content; driver verification and unsaved perception edits stay separate from GET state. Workspace catalog failures are shown as errors, never as an empty workspace list. Retrying a read never replays a write, and a successful perception save supersedes any earlier read.

Replay separates playback sampling from event inspection. Playback loads bounded 30-second frame windows; the frame API accepts at most 60 seconds per request. Event windows can cover up to 15 minutes without expanding the frame window. Precise elapsed-time entry, ten-second jumps, and the seek bar move within the selected run or cycle. Missing samples and recording gaps remain visible; a later frame must never be shown as evidence for an earlier time.

Replay event search reads the entire selected run or cycle through the server's existing archive index. It matches literal, case-insensitive titles, statuses, event types, and identifiers, with an optional track filter; it does not search arbitrary payloads or expand artifacts. Each response scans at most 500 event candidates and returns at most 100 matches. The interface continues through empty scan pages automatically, permits cancellation and retry, and keeps displayed result batches bounded. Cursors bind the query and scope to a source generation and fixed event snapshot: appended events require a fresh search, while rewritten sources invalidate old cursors. Finishing that snapshot is distinct from indexing the whole archive; only both `scan.complete` and `coverage.complete` justify an exhaustive result or a definitive empty state.

Replay evidence links preserve workspace, run, cycle, and time together with `replayItem`, or `replayRecord` plus `replaySequence`. Native links support new tabs and browser history. Details show recorded identifiers, times, status, source text, and exact model inputs where recorded; missing input media is not replaced with a nearby screenshot. Truncated text is labelled and the full record remains available in the raw-data disclosure. Invalid or unavailable references stay explicit. Seeking, searching, copying links, reading details, and retrying reads never start a driver, model, or game or change host control.

Replay evidence uses a compact **Recorded evidence** header with a persistent **Close** action. The full title, recorded text, exact inputs and metadata scroll in the content region, so long records and late-loading images do not move Close out of reach. Source identifiers and raw JSON start collapsed. Selecting different evidence starts its content at the top; closing preserves playback time and restores focus to its opener when available, with a navigation fallback for direct links.

## Interaction Conventions

- Associate form controls with a `Label`, and help text via `aria-describedby`. Icon buttons must have an accessible name.
- Dialogs must have a title and description, focus the first useful input, restore focus to the opener on cancel, and focus the result after a successful creation. Keep in-progress creation visible instead of allowing an accidental dismissal.
- Give buttons an explicit `type`; use `submit` for the submit button of a native form and `button` for everything else.
- `NativeSelect` keeps native option, empty-value, and keyboard behavior; use `Switch` for discrete toggles and `Slider` for numeric ranges.
- Request-detail tabs use the shared `Tabs` primitive for Arrow, Home, and End navigation; inactive panels remain unmounted.
- Whole-row evidence and timeline hit targets may keep native buttons with explicit types and visible keyboard focus. The replay seek bar keeps its native range to preserve continuous millisecond seeking and URL commits on pointer/key release; hidden sound-file inputs remain native.
- Sliders with backend writes update the local value on `onValueChange` and persist on `onValueCommit`, avoiding request storms while dragging.
- Feature requests, pending states, error feedback, and desktop-capability detection are owned by the page; UI primitives handle only presentation and interaction.

Acceptance uses `npm run typecheck`, `npm test`, and `npm run build`, plus checking pages and form actions under an isolated `LUDENS_HOME`. See [Console Debugging and Verification](../tutorials/debugging-and-verification.md).
