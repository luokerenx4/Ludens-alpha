OMP 传输层专项测试从公开的 Provider API 与 Agent 入口调用固定依赖，测试代码与夹具保存在本仓库内，不侵入 OMP 源码或补丁文件。未来若更换 Shiori 底层实现，应独立评估这些传输契约，不将 OMP 的内部实现细节固化为通用接口。

## Codex WS 恢复专项 · 2026-10-20

**本专项属于架构施工期的 TDD 特例，而非全项目的常规测试规则。** 由于数小时长周期运行陆续暴露出相邻的 WebSocket 故障分支遗漏，我们采用“先复现外部故障工况、确认旧实现失败，再收敛恢复策略”的方式闭环。未来架构调整时应重新评估用例价值，不为迁就测试而保留旧架构。

## 构建依据

- **R1（连接时长上限到期）**：2026-10-18 Besiege 6 小时运行，在空 `thinking` 块后收到 `websocket_connection_limit_reached`；早期补丁仅覆盖了该显式到期错误码的恢复。
- **R2（中途 `1012` 关闭未恢复 WS）**：马造 8 小时运行 `2026-10-19T13-19-53.903Z`。北京时间 23:19:59 触发连接上限到期并于 23:21 恢复 WS；但 23:46:56 收到 `websocket closed (1012)` 后，后续约 5.5 小时一直停留在 HTTP SSE 未再切回 WS。根因是关闭码恢复分类缺失（日志本身不推断服务端重启或网络抖动的具体外部原因）。
- **R3（工具参数流式传输中途到期）**：运行 `2026-10-20T14-57-50.713Z` 在 UTC 15:57:52 到期断开时，`custom_tool_call_input.delta` 尚未接收完毕。此前额外添加的“可见输出后禁止重放”拦截严于 OMP 原生逻辑，导致当前轮直接报错退出。修复方案是移除该额外拦截，直接复用 OMP 原生的 `canSafelyReplayWebsocketOverSse` 边界：**仅在完整工具调用交付（`toolcall_end`）后禁止重放；未完成的参数 delta、普通 `text` 或 `thinking` 流中断均允许通过 SSE 安全重放恢复**。
- **S（合成邻近工况）**：矩阵中的其余关闭码、握手失败、超大帧与取消用例均为合成故障注入，用于验证状态机完备性，不声称曾在 R2 中实际发生。关闭码定义参考 [IANA WebSocket Close Code Registry](https://www.iana.org/assignments/websocket/websocket.xhtml#close-code-number)。

## 环境与观测范围

- 测试运行在 Bun 1.4 与打补丁后的 `@oh-my-pi/pi-ai@18.9.1` 上，直接调用真实的 `streamOpenAICodexResponses`（每条用例使用独立 session）；R3 用例进一步通过 `pi-agent-core` 的公开入口 `Agent.prompt` 真实触发工具回调并提交结果。
- 使用进程内夹具替换全局 WebSocket 与 HTTP `fetch`，配合合成 JWT token，完全离线，不读取本机凭据，也不连接模型或模拟器。
- 通过虚拟推进 `Date.now` 模拟 60 秒冷却窗口（握手 watchdog 设为 `0ms`，首事件 watchdog 设为 `1ms`，退避采用受控 scheduler），精确断言请求次数、会话状态、交付块与序列化请求体。

## 工况矩阵

| 工况类别 | 来源 / 故障注入点 | 必须观察到的恢复行为 |
| --- | --- | --- |
| 正常首帧、增量续传、连接替换 | S · 正常完成后旧 socket 关闭 | 新连接发送完整历史且不带旧 `previous_response_id`，下一轮恢复增量 delta。 |
| 显式连接到期 | R1 / R2 · 空 `thinking` 后收到到期 error 事件 | 当前请求自动回退 SSE 完成；60 秒冷却期内不发起 WS 握手；冷却结束后以全量历史重连 WS，下一轮恢复 delta。 |
| 中途临时关闭（`1000 / 1001 / 1006 / 1011 / 1012 / 1013`） | R2 的 `1012` + S · 空 `thinking` 后连接关闭 | 走同一临时故障恢复策略（当前请求回退 SSE + 60 秒冷却后重连 WS），绝不永久禁用会话的 WS 能力。 |
| 握手期临时失败（`1006 / 1012 / 1013` 或握手超时） | S · 连接尚未打开时失败 | 当前请求回退 SSE，冷却期内不重复握手，冷却后建立新 WS 连接。 |
| 协议/数据/策略永久拒绝（`1002 / 1003 / 1007 / 1008 / 1010` 及 `3000 / 3003`） | S · 握手或首帧被拒 | 保持当前会话永久禁用 WS（全部走 SSE），时间推移或上下文压缩均不自动解除。 |
| `send` 抛错、损坏 JSON、首事件超时 | S · 尚无任何内容交付前 | 执行有界重试，耗尽后回退 SSE 并进入冷却；后续正常请求可恢复 WS，无无限密集重连。 |
| `text` / `thinking` 部分输出后到期或 `1012` | S · 流式输出中途注入 | 允许原生 SSE 重放恢复；不把已展示部分文字等同于已执行副作用工具；后续经冷却恢复 WS。 |
| 完整工具交付后到期或 `1012` | S · `toolcall_end` 之后注入 | 当前请求返回 error，绝不向 SSE 重复重放已提交工具；会话仍保留冷却后恢复 WS 的机会。 |
| 工具参数未完成时到期 | R3 · `custom_tool_call_input.delta` 后、`done` 前注入 | 在同一次 `Agent.prompt` 内通过 SSE 重放恢复，完整工具回调**恰好执行一次**并提交结果；冷却后恢复 WS。 |
| 本地 UTF-8 帧 `> 15 MiB` 或远端返回 `1009` | 尺寸回归 + S | 当前及后续请求走完整 SSE 并标记尺寸阻断（期间不反复尝试 WS 握手）；仅当原生上下文压缩完成后解除阻断并恢复 WS。 |
| 累计历史 `> 15 MiB` 但单次增量 delta 很小 | S · 增量续传阶段 | 严格按实际出站帧字节数判断，正常继续使用增量 WS。 |
| 已交付工具后收到 `1009` | S · 工具提交后超限 | 当前请求不重放工具，同时记录尺寸阻断；后续走 SSE 直至压缩完成后恢复 WS。 |
| 人工交还或预算取消（握手中 / 部分输出后 / 拒绝同时取消） | S · 触发 `AbortSignal` | 立即以 `aborted` 结束，不发额外 SSE 回退请求，且不污染后续请求的传输状态机。 |

核心设计准则：**连接恢复分类**与**当前请求能否安全重放**正交解耦——重放安全性完全遵循 OMP 原生 `toolcall_end` 提交点；连接状态机则依据标准 WebSocket Close Code 区分“临时断连冷却（60s）”、“帧尺寸超限阻断（待压缩解除）”与“协议/鉴权永久拒绝”。
