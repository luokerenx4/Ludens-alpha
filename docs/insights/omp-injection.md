# 注入收敛为纯感知通道

`captureContext` 曾在 prompt 开始和工具批次结束时主动追加感知内容，以及变化的控制状态和技能/记忆索引。2026-10-28 起，自动通道只交付新感知记录和采样器状态变化（`state/codeSHA/error`）。控制状态、技能与记忆由模型按需经工具查询。

## 为什么删控制推送

运行身份、进程和日志配置等信息适合故障排查，不需要随着控制状态变化主动进入模型上下文。移除这部分推送后，运维信息仍可从日志与 `rsa status` 查询，自动通道专注于环境观察和感知故障。

## 为什么删技能/记忆索引推送

技能和记忆索引曾在首次完整交付，随后追加变化；模型仍需通过工具读取正文。收敛后不再逐轮生成版本快照或推送索引，文件的读取、修改与使用由原生工具和日志记录。`observation_context` 收据不再写入 `skillVersion/memoryVersion`，`consolidation` 也不再仅因索引变化产生收据；工具实际返回的媒体仍按交付事实登记。

## 感知状态变迁必须推：静默不能有歧义

没有新记录和采样器故障都可能表现为静默。自动注入开启时，需要交付采样器状态变化，帮助模型区分两者：`state` 报告生命周期状态，`codeSHA` 标识该代源码，`error` 给出修复相关的失败原因。状态由感知 worker 的生命周期更新，交付层只选择这些字段做变化比较。

## 收敛暴露的 bug：被压制的交付不能丢状态

最初的收敛实现用 `lastPerceptionState` 去重，却在关闭自动注入、显式 `observe` 或同批已交付时空轴图片时仍更新这个游标。状态文本没有发出，却被记成已交付；恢复自动注入后，如果状态未再次变化，这次故障通知就会被跳过。上下文替换时也漏掉了状态游标的重置。

修复（`f5431b6`）只在允许自动交付、且相关异步读取成功结束后推进游标。被抑制或取消的交付保留待交付状态；压缩、切换会话等上下文替换会清空游标，使当前状态能再次交付。[回归测试](../../rsa/tests/omp-tools.test.ts) 覆盖注入关闭、显式观察、同批图片、上下文替换和读取取消，确保未发出的状态不会被去重吞掉。
