# 注入收敛为纯感知通道

`captureContext` 曾在每轮 prompt 开始与工具批次结束时主动向模型上下文追加三类内容：感知记录、变化的控制状态，以及技能与记忆索引。自 2026-10-28 起，自动注入通道收敛为**仅交付新感知记录与采样器状态变迁（`state / codeSHA / error`）**；控制状态、技能与记忆改为由模型按需通过工具查询。

## 为什么删控制推送

运行身份（`runId / epoch`）、进程状态与日志诊断级别等元数据主要用于运维排障，无需随控制状态变化主动塞入模型对话历史。移除控制状态自动推送后，相关运维信息仍可通过运行日志与 `rsa status` 随时查阅，使模型自动上下文专注于环境观测与感知健康度。

## 为什么删技能/记忆索引推送

技能（`skills/`）与记忆（`memory/`）索引此前在首轮完整推送、后续轮次推送变更摘要，而模型真正消费内容仍需调用 `read` 工具读取文件正文。收敛后系统不再逐轮生成版本快照或主动推送文件索引，文件的读取、修改与实际调用完全由 OMP 原生工具与事件日志记录；`observation_context` 收据不再写入 `skillVersion / memoryVersion`，`consolidate` 维护轮也不再仅因索引变化生成空收据，工具实际返回的媒体仍按交付事实登记。

## 感知状态变迁必须推：静默不能有歧义

当自动通道没有新观测记录进入上下文时，可能源于“画面尚无新采样”，也可能源于“采样器发生故障或未实现”。为避免静默产生歧义，在自动注入开启期间，系统必须主动推送采样器的状态变迁：

- `state`：报告采样器当前生命周期状态（如 `running`、`error`、`stopped`）；
- `codeSHA`：标识当前加载的 `perception.py` 源码版本；
- `error`：提供可直接用于定位和修复代码的异常信息。

状态由常驻感知 worker 的生命周期实时更新，交付层仅选取上述三个字段进行增量比对。

## 收敛暴露的 bug：被压制的交付不能丢状态

最初的收敛实现使用 `lastPerceptionState` 游标对状态文本去重，但在以下场景中，尽管状态文本因策略被抑制而并未真正发给模型，代码却依然提前更新了 `lastPerceptionState`：

1. 自动注入被显式关闭（`rsa perception inject off`）；
2. 同批工具中包含显式 `observe` 调用；
3. 同批工具已交付时空轴图像。

这导致一旦状态游标被提前推进，后续当用户重新开启 `inject on` 或进入下一轮自动交付时，只要采样器状态未发生二次改变，原本未发出的故障通知就会被永久跳过。此外，在上下文压缩或切换会话等上下文替换场景中，原先也遗漏了对状态游标的重置。

修复提交（`f5431b6`）确立了严格的游标推进不变式：**仅当自动交付处于开启状态、且相关异步读取与消息组装成功完成后，才推进 `lastPerceptionState` 与主通道记录游标**。被抑制或中途取消的交付保留待交付状态；发生上下文压缩或会话切换时清空游标，确保最新状态能重新交付。[omp-tools.test.ts](../../rsa/tests/omp-tools.test.ts) 覆盖了注入关闭、显式观察、同批图片、上下文替换与读取取消五类回归场景。
