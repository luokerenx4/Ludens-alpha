# Insights · 为什么这么做

这里不放枯燥的参数字典，而是聊聊我们在把 Coding Agent 扔进游戏和实时交互环境时，**到底踩了什么坑、当时为什么非得这么设计不可**。

很多设计如果只看代码（比如为什么给 OMP 打了一堆压缩和 WebSocket 补丁），会觉得“为什么要搞这么复杂”。但一旦你把视角切换到**“连续感知以 30Hz 采样、模型按轮次读取选中的多模态观测、一跑就是七八个小时”**的真实场景里，这些取舍就会变得非常顺理成章。

## 现存笔记

- [**OMP 后台压缩改造**](omp-compaction.md)：OMP 的主循环是串行的，而原生后台压缩会因上下文增长作废候选。实测增长量说明这一规则可能让候选无法保留到阈值，并增加前台同步重算的风险。这篇讲我们怎么改掉它的压缩结构。
- [**WS 恢复测试依据**](ws-recovery.md)：多模态交互里的图片实在太大了，如果不走 WebSocket 增量（delta）传输，每一轮推理都得把前面所有轮次的历史大图重新上传一遍，上下文膨胀起来简直要人命。这篇讲我们在连续跑了几个 6～8 小时的真机实验后，是怎么给 Codex WebSocket 通道打满恢复补丁与离线故障矩阵的。
