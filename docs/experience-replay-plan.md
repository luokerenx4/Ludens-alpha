# 统一时空轴与经历回放施工方案

状态：已实现并验证（2026-10-27）。先完成本方案，再以 goal 推进施工。

## 目标

感知、动作、模型调用和日志都能定位到 workspace 同一条时间轴上的位置或区间。Dashboard 能像视频播放器一样播放、暂停、拖动和调整速度，画面与其他轨道随播放位置联动。人和 Agent 使用现有记录与引用，不产生第二套录像原件。

本轮的“对齐”采用已有墙钟时间和显式来源关系。保留原始 clock、trace、recordId 等身份即可，不做硬件校时、逐帧测量、设备状态重演或 OMP 调度改造。播放历史不会控制设备、请求模型或启动采样。

## 存储和关联

- `.rsa/timeline/` 继续保存感知记录和媒体原件；连续播放读取实际采样记录，包括没有被模型读取的帧。
- `logs/<run>/events.jsonl` 继续保存动作、模型和工具事件；`.rsa/archive/` 继续保存共享正文。原始文件不迁移、不复制。
- 一个轻量回放投影将它们统一为 `id / kind / startAt / endAt / sourceRef`。时间为 UTC 毫秒，展示时转换本地时间；模型输入通过已有 observation/record 引用关联，工具和动作通过既有 trace/actionId 配对。
- 索引只保存位置、摘要和引用，使用现有可重建 `.dashboard-index/` 与有界缓存；正文、图片、音频仅在当前窗口或选中详情时读取。不引入数据库、新服务、独立媒体存储或全量内存列表。
- 工作区是共同坐标域；第一版在现有 project/run/epoch 选择范围内播放，切换 run 仍使用相同绝对时间坐标与 workspace 媒体。正在运行的区间可以刷新尾部，但不强行把浏览历史的用户拉回最新。

## 读取接口

Dashboard 增加 `/api/replay`，使用现有 project/run 注册与路径校验：

1. 概览：所选范围的开始/结束、轨道概况；读取轻量索引，不展开模型请求正文。
2. 时间窗：返回有限区间内的感知记录、动作/模型/工具跨度及日志摘要，并包含窗口开始时仍有效的前一帧和跨窗口跨度。设置窗口和条目上限，分页不静默漏掉历史。
3. 详情：按稳定来源引用读取选中记录/事件；保留结构化感知、模型输入关联、参数/结果与错误。大正文按需展开。
4. 媒体：通过记录 ID、序号与媒体序号验证后读取同轴原件，不接受任意磁盘路径。未录制、已过期和缺失内容显示明确状态。

离线日志无需活着的 Host。所有读取均为只读；查询/播放不能改变 Alice 关注目标或设备控制权。

## 前端

新增“回放”视图，复用 Dashboard 的工作区、run、epoch 选择和视觉样式：

- 主要区域展示当前感知记录的所有图像，双屏自然并列；无需了解游戏或固定屏幕布局。其他媒体/JSON 可在详情查看。
- 播放/暂停、可拖动进度条、时间显示、倍速、前后采样帧跳转；播放使用浏览器时钟，不按模型请求数推进。无新图时保持最近已记录画面并显示采样时间。
- 感知、动作、模型调用、日志使用同一游标。跨度条显示持续区间，日志随当前时间窗口更新；点击条目可定位时间和展开来源详情。
- 跳转时间可写入 URL 以便刷新与分享；每帧推进不触发路由更新或全量 run 请求。切换工作区/run/epoch 取消旧请求，迟到响应不能覆盖新选择。
- 客户端只保留邻近时间窗并预取下一窗；媒体加载失败可跳过并继续，查询失败有重试入口。正在运行的日志允许手动刷新尾部；普通历史回放与实时运行互不干扰。

第一版不做剪辑导出、视频编码、全世界状态恢复或可视化编辑器；选取时刻与来源定位给后续剪辑提供基础。

## 施工顺序

1. 创建 goal，冻结上述验收范围；确认当前运行只读，不改 Agent 文件或重启游戏。
2. 定义共享回放 DTO 和查询边界，补感知段索引时间窗读取及媒体读取。
3. 增量构建事件回放投影，把模型、动作、工具与日志挂到同一轴；补概览、窗口、详情 API。
4. 实现独立播放器、轨道与详情，接入现有导航和选择状态。
5. 同步现行 logging/workspace/architecture 文档，修正旧范围说明。
6. 离线测试、类型检查与隔离 production build；用当前新马造记录做只读浏览器验收。审查范围后提交，不自动推送未经本轮要求的提交。

## 验收

- 前端从任意已记录时刻播放、暂停、拖动、倍速，当前双屏随真实采样变化；动作、模型与日志保持同一播放位置。
- 前一帧、稀疏采样、跨窗动作、失败/取消/未结束跨度、同时间事件、多个 epoch、尾部新增都可查询；只按已有身份配对。
- 模型输入能追到实际引用的观测，历史帧不会被最新设备截图替代。普通未录制媒体不会被伪造为可播放。
- 连续采样中未进入模型的记录也可播放；关闭 Host 后仍可回放已持久化历史。
- 分页/时间窗有界，冷查和重复拖动不将全部媒体/正文/索引塞进内存；切换后旧请求无效。原始媒体、session、events 文件不因回放产生副本。
- 真实浏览器验证导航、播放、暂停、拖动、倍速、条目详情、空记录/缺图；记录实际验证结果和限制，不以编译成功代替播放器能用。

## 验证结果

- Dashboard 全部 142 项测试通过；类型检查与隔离目录的 production build（webpack）通过。离线用例覆盖多感知通道、跨窗跨度、分页与新增事件隔离、epoch 边界、取消与晚到终态、单点记录、媒体路径和缺失、模型重编码及跨周期历史输入。
- 真实浏览器使用 2026-10-27 新马造 30 分钟记录，验证回放导航、无感知时的空状态、第一帧跳转、双屏加载、8 倍速跨窗播放、暂停后位置不变、拖动、动作详情、模型实际输入图片，以及刷新后保留 URL 时刻。真实记录约每秒采样，播放器保留该采样密度，不补造中间画面。缺失媒体的响应与路径边界使用离线用例验证，未删除真实媒体制造错误。
- 独立冷进程读取该真实日志：概览初建 5.75 秒，RSS 从 79 MiB 到 269 MiB；随后 20 个 30 秒窗共 24 页、5389 条，读取约 273 ms，GC 后 RSS 271 MiB、heap 19 MiB。共享热页缓存 31.7 MiB，未越过 32 MiB 上限。这是回放读取器验证，不代表整个 Next 开发服务器的内存上限。
- 原生预算后的持续采样被保留在完整 run 中，所选 epoch 正确截止于 08:00:13.671 UTC。验证只读取现有记录，未启动模型或控制设备；没有复制媒体、session 或原始事件。
- 开发态 Next 曾保留修改前的索引类实例；重载 Dashboard 后重新验收通过。部署本变更需要完整重载 Dashboard，不能只依赖开发热更新。模拟器与宿主无需重启。
