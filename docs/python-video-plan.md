# RSA 双语言工程与视频感知存储

状态：已实施并完成离线验收。2026-10-27。

## 目标与边界

RSA 正式由 TypeScript 与 Python 共同实现。TypeScript 负责 Shiori/OMP 接入、控制权、生命周期和产品接口；Python 负责常驻感知、科学计算接口和时空轴媒体编码。组件边界按职责划分，不要求两种语言实现重复接口。

本次把现有 Python 代码正式包化，并使用 PyAV 将显式 `@record` 的图像连续编码为视频。验收包括当前观测、历史查询、模型日志引用、Dashboard 回放和停机后浏览。Baseware 仍只负责设备能力；不要求 driver 录像，不修改 OMP 本体，不新建常驻录像服务，不手动迁移 AI 的感知逻辑。保留非视觉感知、现有时空轴和运行日志的归属。

## 1. Python 是正式工程组件

- 保留 `rsa/src/` 与 `rsa/python/` 目录。后者用 `pyproject.toml` 声明 `rsa_tools` 包、Python 版本、运行及开发依赖，用独立锁文件固定依赖。
- PyAV 和现有 jsonschema 属于框架依赖；AI 的训练模型和任务依赖仍由 workspace 自己管理。
- 开发安装在 RSA 项目环境，实际运行继续由 `RSA_PYTHON` 选择解释器，不改用户全局训练环境。正式包可在仓库外导入，不依赖从 `__file__` 猜仓库位置；schema 等资源包含在包内，并维护唯一来源。
- 保留现有 `python -m rsa_tools._perception` 入口，其他框架 Python 入口同样使用模块形式。源码注入只承担开发及已有 Baseware 客户端定位，不代替包依赖声明。
- Python 测试与基础类型检查有明确命令，并纳入 RSA 统一检查入口。优先检查公开边界及新增实现，避免为旧代码全面加类型而扩大改动。

## 2. 编码归属与生命周期

现有 TS Host 启动常驻 `rsa_tools._perception`；它拥有 `ObservationHistory` 单写入者，加载 workspace 的 `Perception`。在内部视频模块延迟 `import av`，由单写入者管理编码器。普通脚本的 `@record` 仍向这个写入者提交，不各自创建编码器。

每个能力的媒体位置形成独立图像流，尺寸、格式、generation 或时间基准改变时换段。不猜测上屏、下屏或摄像头语义。AI 输出的文字、结构化数据与非图像媒体沿现有路径保存。

编码在现有进程内的后台线程运行，队列同时限制字节和任务数；热原图仅在有上限的内存窗口内保留，供当前观测使用。编码积压或单帧超限时明确标记录制缺口，不能无限堆积、阻塞采样或宣称归档成功。关闭/热重载停止提交，完成队列、flush 并关闭编码器；异常留下可诊断状态。

## 3. 媒体格式和引用

- 图像默认使用 H.264 / MP4、高质量有损编码，选取本环境 PyAV 可用的编码器；通过运动、小字和颜色样本验证。保留原尺寸；编码器尺寸约束通过可逆边界处理记录，不任意缩放。
- 按实际记录时间赋予 PTS，保留 `sampledAt` 和原采样时钟元数据；不把目标采样率伪造成实际采样率。时间倒退等不连续处换段。视频不会补出未采集的动作细节。
- 时空轴 JSON/索引仍默认一小时分段。媒体采用短片段（初始 10 秒），避免等一小时才能查看及大段异常损失；这是两种不同的分段职责。
- 媒体的逻辑类型仍可以是 `image/png`，`timeline` 引用增加 `video` 定位：视频 asset、PTS、timeBase、尺寸。模型拿到图片；播放器可直接使用视频。引用的具体 TS/Python 字段在实现中统一，不能再要求每个媒体都有图片文件 `path`。
- 每段有小型状态文件，区分 pending、ready、error；只有完成的段对视频播放承诺可读。被拒绝的帧保留 gap 原因，不悄悄用邻帧代替。引用和状态查询均按需读取。
- 当前结果优先直接返回内存原图。冷历史按视频定位解码为图片；临时解码不生成永久第二份原图。关闭持久化时仍服从现有热窗口与字节上限，退出清理临时媒体。

## 4. 模型与日志引用

`@record` 的录制图像不再保存完整 PNG/JPEG 套。OMP 图像标准化及终端图像的 `derive` 只登记来源帧、变换描述、交付 hash/字节数，沿用同一视频源，不再额外归档每帧压缩版本。

hash 保留为当时交付身份；有损历史解码不声称与当时输入逐字节相同。日志引用与 Dashboard 对这点明确标注。OMP 自己的 session/blob 由上游管理，本次不修改。非录制媒体也不被日志隐式另存一份。

跨语言共享引用契约，路径只允许已授权 workspace 内的媒体；校验规范路径、真实路径、记录归属，拒绝目录穿越和 symlink 逃逸。

## 5. Dashboard 和离线读取

- 回放索引只保存小型定位元数据；同段视频使用稳定 URL。图像及模型输入详情需要单帧时走按需解码。
- 视频通过文件流及 HTTP Range 提供，不 `readFile` 整段，不进入 Next 的全量媒体缓存。取消请求释放文件句柄。
- 保留时空轴主播放时钟；各视频随播放/暂停、倍速和拖动同步，同段连续播放，只有跳转或偏差时纠正位置；切段复用已有缓冲体验。双流独立解码，共享游标。
- 感知进程停止后仍能读取视频及历史单帧。复用 Python 解码模块的短生命周期离线入口，限制并发、输出与缓存，不新增常驻服务，不启动设备或采样。
- 历史图片记录继续按现有格式读取，不批量重编码、删除用户档案或重写旧日志。

## 6. 实施顺序

1. Python 正式包化、可复现安装、资源路径和统一检查。
2. Python 媒体编码/定位/解码与有界录制队列，接入现有单写入者。
3. TS 观测、derive、日志归档消费新引用，确保不复制图片。
4. Dashboard Range、单帧读取、视频回放与时空轴同步。
5. 集成验证、更新现行架构/开发/workspace/日志文档，审查改动并提交。

## 7. 验收与限制

- 干净安装及 wheel 在仓库外导入；TS/Python 统一检查通过。
- 合成双流、不均匀时间、尺寸变化、跨段、热重载、停止后冷查询均返回正确定位；检查图像内容，不只检查调用成功。
- 验证 queue 满、pending、编码失败、热窗口淘汰和持久化关闭；清理后无泄漏 worker/文件句柄/原图套。
- 持续双流压测记录进程 RSS、队列峰值、热缓存预算、输出体积；以测得趋势说明结果，不把 Python 分配器统计当总 RSS。
- 验证当前观测到 OMP 标准化、日志引用、历史重建整条链路，明确有损复原限制。
- 视频 Range 的完整/部分/越界请求、取消、路径限制和大文件内存验证；停 worker 后浏览历史。
- 浏览器验证播放/暂停、拖动、倍速、双流和跨段；不能仅凭后端响应宣称播放流畅。
- 使用离线合成样本和现有录制数据验证，不开启模型实验或操控真实游戏。实际长时游戏与硬件编码收益另行实跑评估。

## 施工结果

实现沿用现有 TS Host → Python 常驻感知进程。`rsa/python` 是带 `pyproject.toml`、`uv.lock`、包内 schema 和类型检查的正式包；模块入口和离线解码共用解释器选择。OMP shell 注入 `RSA_PYTHON`，明确调用它可使用相同环境，裸 `python3` 继续服从用户 login shell。

图像通过进程内有界编码线程写入 `video/<id>.mp4`，引用为 `timeline: {recordId, sequence, asset, video: {pts,timeBase,width,height}}`；`data` 仅用于当次交付和有界热层。冷读解码在采样锁外执行，关闭后可独立读取。非图像对象仍沿用原存储。模型标准化图片和 benchmark 附件只登记同源引用，`approximate` 明示有损复原。

日志新增小型消费索引 `.rsa/archive/media/<sha>.json`，只为真正进入日志的图像保存 hash→视频引用，解决 4096 项内存映射淘汰和重启续会话后旧图失去定位的问题；不对每个后台采样写这个索引、不保留图片字节。稳定有效来源可以复用，窗口或失败来源可被新记录替换；具体采样时间仍在原观测引用中。

验收结果：

- RSA TypeScript 检查、Python mypy 全包检查通过；225 项 TS 测试和 35 项 Python 测试通过，3 项真实设备测试按离线范围跳过。覆盖 OMP 原生 bash、跨轮后台程序与人工交还、CLI 历史图像、视频引用、缓存淘汰和重启。
- 最终 wheel 在仓库外新环境安装，并用 `python -I` 检查包、schema、入口和类型标记；不依赖源码路径。已安装包独立读取既有第 1234 条时空轴记录并解码出 320×240 PNG，没有启动 writer 或采样。
- Dashboard 150 项测试、类型检查和生产构建通过；构建保留 3 条已有动态文件追踪警告。8 GiB 稀疏文件末尾 Range 查询只读取所需 4 字节，没有整文件 Buffer。
- 浏览器使用 12 秒离线双流样本验证播放/暂停、1×/2×、跨 3 段及定位到 6 秒，两路媒体时间均为 2.0 秒；停采后历史图像 API 返回可读 PNG。视频按段稳定 URL 读取、至多保留当前与前一段两个解码面，待新段解码完成再切换画面。
- 80 秒双流压测：每秒 30 条记录，共 2400 条／4800 帧，0 丢帧，队列峰值 1.87 MB／8 帧；进程 RSS 峰值 90.1 MB，中段均值 87.5 MB，尾段均值 89.4 MB。
- 该合成样本视频 3.04 MB，对应原 PNG 累计 16.57 MB，约缩小 5.45 倍；永久原图文件为 0。抽查 10 个冷帧，最大平均像素误差 0.99／255。数据来自移动边缘与小字合成双屏，并非游戏画质或所有分辨率的保证。

可复跑压力检查（输出目录必须不存在）：

```sh
uv run --project rsa/python --frozen python rsa/scripts/verify-video-storage.py \
  --output /tmp/rsa-video-soak --records 2400 --rate 30
```

限制：H.264 使用 CPU `libx264`、CRF 18；历史预览不等于当时模型输入的字节副本。AI 当前观测可立即拿热图像，Dashboard 的视频/历史图像要等待当前片段收尾，通常约 10 秒，编码排队还会增加等待。无后继样本的最后一帧使用 1/30 秒尾长；随后保持末画面。队列/热层预算不等于进程 RSS 上限，80 秒压测不能证明整夜运行的上界。本次没有开启在线模型或真实设备试验；旧图片档案未批量转换。
