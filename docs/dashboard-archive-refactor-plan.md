# Dashboard 档案读取重构方案

状态：2026-10-27 已完成实现、验收与本地提交。本文是本次施工与验收清单；稳定接口同步到 architecture.md、logging.md 和 development.md，不另维护第二份接口说明。

## 问题与目标

当前 Dashboard 把原始事件加工为展示正文、关系指针和回放目录，HTTP 读取又等待全部加工完成。2026-10-27 的 30 分钟录像产生 518,252 条事件、470 MB 原日志和 2.63 GB 派生索引。32 MiB 页缓存正常生效，但常驻队列的已完成 Promise 与 Next 开发态异步调试图共同保留历史对象；现场 GC 后仍有约 7.3 GB JS 堆。

本次重构以“事实持续产生，消费者按范围读取”为边界。固定时间窗与一页日志的工作集应有界；回放媒体不等全量诊断整理；请求结束及任务空闲后释放引用。全量历史、事件原始身份、模型输入来源和 Pet 增量消费继续可用。

## 存储归属

| 数据 | 唯一正文来源 | 可重建目录 |
| --- | --- | --- |
| 运行事件 | logs/<run>/events.jsonl | 事件位置、文件偏移/长度、时间/epoch/type、必要关系定位 |
| 模型流与工具正文 | streams 与 workspace .rsa/archive | 模型/展示版本的来源位置与截止游标 |
| 感知记录 | workspace .rsa/timeline/segments | 复用现有 64 字节索引、段摘要 |
| 视频与其他媒体 | timeline/video、timeline/objects | 原引用及单条记录的归属校验 |
| 小型统计 | 从事实计算 | 计数、时间范围、生命周期状态；不复制完整事件正文 |

不改 OMP 原生日志、原事件格式、模型行为、感知函数或设备驱动，不迁移/删除事实数据，不引入数据库、独立网络服务或通用执行框架。

## 读取边界与进程

Next 负责页面、同源校验、参数解析和有界 HTTP 响应。文件检索、索引整理、历史聚合由一个 Node worker_thread 承载；worker 随 Dashboard 存亡，不另监听端口、不新增 launchd 服务，不导入 Next/React。

使用组件现有 TypeScript 工具链启动 worker，薄 JS 引导加载 TS；开发与生产共用同一协议。客户端模块不导入 data/activity/replay 的实现，localRequest 单独拆出，避免间接把重型后端重新装入 Next。视频授权在 worker，Next 用现有 Range 文件流输出，不经 RPC 复制整段媒体。

RPC 只有现有业务查询的类型化操作、requestId、结果和错误；不增加第二套业务语义。请求 AbortSignal 转成取消消息；删除等待者并终止其读取/解码。并发相同索引构建共享任务，消费者取消不能破坏其他读者；没有消费者的工作在批次边界停止，已提交进度可续。worker 崩溃使在途请求明确失败，下次查询才重建 worker，不自动重复写操作或控制设备。

队列空闲后释放已完成尾引用，保留排队顺序；各任务使用短批次、明确预算和提交边界，不保留贯穿进程寿命的 Promise 历史链。页缓存继续有字节上限，run 按闲置/LRU 回收，任务和 RPC 也有有界生命周期。

## 文件检索目录

1. 原始事件地址只保存一次。不可变事件按位置顺序建目录，不再同时维护重复的 latest/history 地址表。
2. model/span/time 等二级目录保存 key 到事件位置的小引用，禁止复制完整地址、绝对路径和 trace。
3. FileRecords 区分目录项和正文指针：目录项不生成 data-* 正文文件；保留现有分页、缓存、原子提交能力。
4. 普通诊断/系统展示块只存来源位置和必要筛选字段，当前页面才生成文本/data。
5. 模型流、工具与 Python 聚合采用来源配方：模型/组身份、事件截止位置、stream 截止偏移、版本游标。按需从原文重建所请求版本，晚到事件不能把新内容冒充旧 revision。少量计数/状态可物化，不保存完整展示正文副本。
6. 新增原日志按提交游标增量进入目录；已有日志在读取 worker 中分批补建并报告进度。目录是可丢弃产物，格式切换只失效旧缓存。读取不等待与所需范围无关的展示/关系投影。
7. 全文检索允许扫描原文，但按批次取消、限内存，结果分页；不将全量结果数组或整个 events 文件读入内存。

## 回放读取

视频/感知轨道与日志/动作/模型轨道独立查询和分页，共用 UTC 时间游标。感知时间窗直接选择 timeline 段、读取固定长度索引，再读取窗口内所需记录，不生成另一套全量帧目录。

overview 返回可核验的时间范围、通道与整理状态；目录尚未完整时明确表示 coverage/progress，不能把未整理部分当成没有记录。现有摘要缺少 run/epoch 时，在有界目录任务中补齐，媒体查询本身仍可根据记录凭证直接读取。

媒体 URL 携带 recordId/sequence，读取一条原始记录验证 run、asset 和归属后输出原件。视频段使用稳定 asset identity，不能因授权 URL 的 record 变化而每帧重建 decoder。历史模型输入按明确事件引用查询，不能用附近画面替代。

日志轨道使用时间范围和游标；详细诊断不占用视频帧分页预算。前端可以先显示媒体，再逐页补充轨道。索引进度和读取错误独立呈现，取消/拖动不会抹掉已就绪画面。保持现有预读缓冲上限和 Electron 复用方式。

## 迁移与运行

原档案不动；旧 .dashboard-index 是可重建缓存，升级目录版本并重新生成，查询游标按 generation 明确失效。构建中断保留已提交检查点，不能因一次取消删除已完成目录。

常驻启动使用构建后的 Next production；开发者仍可显式 npm run dev。RSA 启动应明确检查/准备生产产物，不能静默使用旧版本或自动影响游戏进程。重载 Dashboard 前核实当前进程身份，保留 Host、Baseware、模拟器和 workspace。Pet 在同一 Dashboard 恢复后继续消费增量。

## 施工顺序

- M1：读取 worker、类型化 RPC、轻量路由、取消与空闲队列生命周期。
- M2：轻量事件/关系目录，Activity 来源配方与按需展示；清理重复正文。
- M3：运行统计与模型详情接到同一读取层，移除整文件/全量正文读取旁路。
- M4：回放直接查询 timeline，媒体与事件轨道独立加载，补建进度可见。
- M5：真实大日志、开发与生产模式验证；重载产品界面，同步文档并提交。

M1–M5 均已完成。M1、M2、M4 在确定接口后并行，集成后统一验收。旧事实格式保持可读，派生缓存不保留旧实现兼容分支。

## 验收与证据

先用有界离线 fixture 覆盖真正的契约：事件/stream 追加、晚到更新与版本游标、源文件替换、跨 epoch、取消/并发、缓存淘汰、媒体越界/归属检查。保留原有有效测试，删除仅验证旧复制结构的断言，不为迁就测试保留旧架构。

再用本次 518,252 条事件和真实录像，原件只读、临时目录生成新索引：

- 核对抽样首/中/尾事件内容、全量可达性、精确模型输入关系、历史版本与 Pet 增量语义。
- 比较旧 2.63 GB 索引与新目录，确认诊断正文不再复制，记录各表与总字节。
- 冷首次打开、视频首播、随机 seek、重复切 run/取消读取，不能被整轮诊断整理阻塞；读取中有明确进度。
- 记录 Next 与 worker 的 heap/RSS、页缓存和任务数；重复读取后应趋于平台，空闲后无历史尾 Promise 保留链。使用受限堆的子进程复现开发态问题；不对生产进程写堆转储。
- 浏览器与 Electron 共用界面实看视频连续播放、时间轴联动和错误反馈；Pet 在线仅证明消费链，不冒充所有姿态视觉验收。
- npm test、typecheck、build；涉及 RSA 启动的对应离线测试。无在线模型请求或设备输入。

归档小型结果、测量脚本与可播放链接，不复制 workspace 或原始大日志。提交前检查范围与大小，报告明确列出未完成或受环境限制的验证。

## 本次测量结果

工况为 2026-10-27 马造录像实验：518,252 条原始事件、469,901,131 字节，406 个已就绪视频段。验证读取原档案，隔离目录重建派生索引；不重新运行模型或游戏。

| 验证项 | 结果 |
| --- | --- |
| 派生目录 | 旧 2,625,583,631 字节 → 新 677,291,021 字节，减少约 74%；正文仍从原件读取 |
| 全量与来源 | 首/中/尾源内容、事件数量、源文件尺寸/mtime、模型输入引用核验通过；完整统计、历史分页最终均 200 |
| 开发态 HTTP | 431 次读取，包含取消、随机拖动、切换 run；读取堆没有沿请求历史持续增长 |
| 开发态内存 | Next 堆峰值约 89 MiB，worker 堆峰值约 44 MiB；重复读取阶段进程 RSS 约 576–577 MiB |

| 生产态内存 | Next 进程含 worker 的 RSS 约 326–393 MiB；20 轮随机拖动阶段约 382–384 MiB；另有约 23 MiB 的 esbuild helper |

| 生命周期 | 取消不会破坏其他读者，闲置 Promise 尾清除，关闭等待队列排空；离线结束后缓存页/运行数归零 |
| Pet | 重建并重启 Electron 后恢复 following，error=null；旧包把 202 当正常日志页的问题通过共享新版客户端消除 |

实看发现的视频尾部停顿也纳入本次验收：实际段最后 PTS 为 9.979 秒、容器时长 10.012333 秒。连续播放按时间游标推进，缺帧恢复或已越过段尾才定位到采样 PTS，避免低频采样把播放不断拉回。缓冲只暂停公共时间游标，不把用户的播放意图改成暂停；段结束保留尾帧并允许进入下一段。初始 1Hz 段中，Chromium 在最后 PTS 9.041 秒报告 ended/readyState=1 的情况也作为回归工况，向前播放不再被终态 seek 标志锁住。回放周期元数据直接来自 control 目录，不因显示下拉选项而触发全量运行统计。

完整统计首次重建仍需几分钟；这不是秒级查询的承诺。冷准备返回可续的进度，媒体和已就绪的时间窗独立可用。以上是本机真实档案与重复读取压力验证，不是连续数天运行的保证，也不将旧录像采集率当作本次播放性能。

小型测量报告与脚本保存在本地 `artifacts/maintenance/dashboard-refactor-20261027` 和 `dashboard-worker-http-3hzxevqs`。验证生成的约 1.2 GiB 临时索引/开发构建缓存已删除；原始事件、会话、workspace 和录像未改。

最终离线检查：Dashboard 173 项测试、Companion 87 项测试通过；RSA 启动相关 17 项测试通过；Dashboard 与 Companion 类型检查、生产构建及构建新鲜度检查通过。

产品界面复核：最终浏览器版本从 00:00 连续播放到 03:36，跨过初始 1Hz 段、采样率切换和多个视频段，随后人工暂停；Electron 从头播放到 00:23，跨过原先 3 秒及 19 秒停顿点。最新/全部周期选择、尾部跳转均核对过。桌宠消费者 following、error=null。该检查不等于每种桌宠姿态均已视觉验收。
