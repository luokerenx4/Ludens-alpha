PLAYNESS / PRODUCT REQUIREMENTS / 2026.10.19 / v1

用同一份日志，验证 Harness 的变化。

流程：现状盘点 → PRD → 图像生成视觉稿 → 实现 → 离线与短模型实跑 → 页面验收。沿用统一控制台的布局与视觉，不新增桌面前端或分析服务。

01 · 问题与目标

现有 Benchmark 是运行剖析：能看耗时与调用链，但缺少固定输入、明确判定和可反复执行的 case。新增四个可运行 case，给每次执行留下条件、检查项、指标与原始证据。把基础设施错误、任务未通过和证据不足区分开；不以测试断言数量、skill 字数或脚本数量衡量能力。

02 · 四个 case

Case执行与判定主要指标
接管中断
offline		真实 Runtime / Baseware / IPC；假驱动执行长动作，原始接口与嵌套 Python 均可中断。输入释放、manual、旧 epoch 不触达驱动，调用正常清理。交还控制、输入释放、调用退出延迟。
WS 到期恢复
offline		真实 Codex provider，模拟到期与 HTTP。冷却期间走 SSE，期满全量恢复 WS，再续接 delta；已交付工具不重放。发送次数、恢复结果、delta 请求体比例。本地耗时与虚拟冷却明确标识。
后台压缩
offline		真实 OMP 原生压缩，延迟响应；保留 256k，快照后追加尾部，跨 epoch 就绪与应用。只提交一次、尾部完整、HTTP 子链明确，取消后不晚提交。摘要请求数、准备时间、前台等待、尾部保留与关联完整性。
重复操作能力复用
live		新工作区、原提示与真实模型。装配台的 PNG 传感器显示当前拨盘目标，控制器只提供设置和提交；连续两批订单。Agent 自主创建装饰器能力、经统一目录发现，并在后批实际复用完成任务。评测逻辑不进入模型提示。任务完成数、能力跨批成功调用、每批决策开销。没写宏也可完成任务，但不能算能力复用通过。

03 · 执行与数据契约

  • 入口 rsa bench list 与 rsa bench run <case|all>。默认只运行离线 case；真实模型需要显式 --live。支持 model、seconds、requests、seed、repeat、output；默认模型沿用 gpt-6.1-sol，live 预算 180 秒 / 30 请求。
  • 每次 case 独立进程、独立新 workspace；标准 AGENTS.md、空 skills/memory，新会话。运行记录仍在该 workspace/logs/run 内。模拟传输只影响 case 子进程，清理 socket 和进程后退出，不影响游戏、Pet 或已有会话。
  • 复用 schema 2 EventLog、原 manifest 与工作区索引。新增 benchmark.json 结果侧文件，包含 schemaVersion、caseId/version、mode、status、时间、参数、代码/提示哈希、checks、metrics、limitations。每项检查引用原始事件 seq；benchmark 自身事件标注 source.component=benchmark。
  • 状态为 running / passed / failed / inconclusive / error / skipped。false 检查表示行为未达标；null 表示证据不足；执行异常为 error；未授权的在线 case 为 skipped。真实模型未学会是有效失败结果，不自动重试到通过。
  • CLI 输出结果位置和状态；失败/异常返回非零退出码。复跑追加记录，不覆盖旧结果。终态文件原子写入，硬超时或进程异常也保留错误结果。

04 · 信息架构与交互

Benchmark 内分“运行剖析”和“基准用例”。前者保留现有请求图、工具、截图和调用链；后者是跨工作区的 case 列表与执行历史，不受当前游戏 workspace 筛选误导。浏览器与 Electron 共用此页面。

  1. 用例页固定四个入口，显示 offline/live、版本、最近结果和最后执行时间；未运行明确显示“尚未运行”。不计算混合总分。
  2. 选中 case 查看最近执行列表；详情包含结果、配置、逐项预期/实际/证据、指标、限制说明。运行中、读取失败、无记录、缺少指标有独立状态。
  3. 可选择同 case/version/mode 的历史记录作基线，显示同名指标差值。模型、预算或 seed 不同则提示条件变化，允许大体比较但不宣称因果。
  4. “查看运行”进入原有运行剖析，携带 project/run/epoch；检查项可定位原事件证据。所有链接从已索引的本地日志构造，不接受任意文件路径。
  5. 页面提供可复制 CLI 命令；本期不在浏览器启动模型或调度长期任务。默认不触发在线费用。URL 保留 tab/case/result/baseline，刷新与返回可恢复选择。

05 · 视觉与可访问性

延续石墨灰 #171918、面板 #202321、暖白 #E9E9E2、金色 #DBBC81，完成用鼠尾草绿，失败用珊瑚红并附文字。顶部短说明与分段导航；左侧紧凑 case 清单，右侧结果与检查表，历史列表置于下方或侧边。原始 JSON 不占主内容，只在证据展开中按需显示。数字有单位，未知用 —，不画假折线或假成功率。

桌面 1440/900 宽可用，390 改为纵向布局；表格局部滚动，页面无横向溢出。原生按钮、清楚焦点、键盘可选记录，状态不用颜色单独表达。

06 · 视觉稿

用 imagegen 生成基准用例页高保真稿，沿用现有控制台。示例数字仅用于构图，不进入产品数据。生成提示保存于本目录，图片与实际验收截图存于仓库外 artifacts/benchmark-design。

07 · 验收

  1. 四个 case 均有可执行 CLI、参数、明确判定和日志证据；前三个用实际生产路径完成离线执行，第四个完成一次有界真实模型尝试，保留实际成绩。
  2. 取消、恢复、压缩与复用的 evaluator 有针对性负例，不会将缺证据或 fixture 写出的脚本计作真实学习。
  3. 多次执行可发现、比较、深链接到原日志；未知状态不补成功；模拟耗时不冒充线上性能。
  4. 真实结果在浏览器页面可读，900/390 响应式、选择/返回、命令复制与证据定位可用；Electron 继续复用同一前端。
  5. 相关检查、类型和生产构建通过；PRD 与小型代码进入 Git，workspace、模型历史、图像和运行日志不进入仓库。

08 · 实现记录

2026-10-19 已实现四个 CLI case、独立进程与 workspace、结果侧文件、只读 API 和基准用例页。按视觉稿实施，实际验证基线比较、证据展开、原运行深链接、URL 刷新/返回、命令复制及 1440/900/390 宽度；页面无横向溢出。截图保存在 artifacts/benchmark-design/actual-*.png。

三个离线 case 多次通过。真实模型 case 使用 gpt-6.1-sol / Low，在约 36.4 秒、11 次模型请求后完成 6/6 订单，自主创建 assembly.py:assemble_order，并跨批直接 import 使用；未通过统一 controller 的发现与复用检查，因此最终为 failed。运行后独立只读 AST 盘点证明“已经创建”，不将它冒充 Agent 主动发现。初始评测及重评原因均保留，无额外模型请求。

针对性离线检查：RSA 11 项（128 断言）通过；Dashboard 60 项、两组件类型检查与前端生产构建通过。取消验证覆盖嵌套 Python 退出和全局传输恢复；后台压缩无 control 的 fixture 可按完整 run 查看，不伪造接管事件。现阶段对直接 import helper 的使用只保留原日志证据，未把它换算成注册能力复用成绩。模拟耗时不代表线上网络性能，dirty provenance 也不是完整源码快照。
