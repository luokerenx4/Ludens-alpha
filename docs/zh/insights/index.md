# Insights · 为什么这么做

本目录记录将 Coding Agent 接入持续采样的实时交互环境时遇到的关键工程问题与架构取舍。

许多设计细节（例如对 OMP 上下文压缩和 WebSocket 传输层的补丁）如果仅看局部代码会显得复杂；但放到**“连续感知以 30Hz 采样、模型按轮次读取多模态观测、单次运行持续数小时”**的场景下，其约束条件与演进脉络就十分清晰。

## 现存笔记

- [**OMP 后台压缩改造**](omp-compaction.md)：OMP 的主循环是串行的，而原生后台压缩会因上下文增长作废候选。实测增长量表明该规则可能导致候选无法保留至阈值，增加前台同步重算的风险。本文说明我们对压缩流程的结构调整。
- [**WS 恢复测试依据**](ws-recovery.md)：多模态交互中的图像载荷体积较大，若不使用 WebSocket 增量（delta）传输，每轮推理都需要重复上传历史图像，长周期运行下传输开销会迅速累积。本文说明基于数次 6～8 小时实测运行归纳的 Codex WebSocket 恢复规则与离线故障矩阵。
- [**注入收敛为轮首单通道**](omp-injection.md)：早期在每个工具批次结束时向最后完成的工具结果追加最新截图，导致约六成上下文消耗在非显式请求的画面上，且归因随并发完成顺序波动。本文说明移除批次末通道、将轮内观察统一收归显式 `observe` 的依据。
