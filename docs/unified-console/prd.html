PLAYNESS / PRODUCT REQUIREMENTS / 2026.10.19

一个控制台，看见整个循环。

浏览器与 Electron 使用同一份前端。Alice 继续陪伴在桌面上，运行详情、性能与设置都回到统一的工作台。

版本 1.0 · 本地产品改版 · 顺序：现状盘点 → PRD → 图像生成视觉稿 → 共享前端与桌面壳 → 真实日志与离线验证。

01 · 要解决的问题

Electron 的运行窗口和网页观察台展示同一次运行，却拥有两套 UI。桌宠详情要跳到浏览器，运行、日志与性能之间缺少连续上下文。新增 Shiori / 能力调用日志已可追踪，现有界面仍以模型请求为中心，来源与执行层次不够清晰。

本次交付一个共享控制台：既能回答“AI 在看什么、做什么”，也能回答“这轮哪里慢、哪里失败”。保持桌宠外观、浮窗行为、点击音效、导入与音量设置；删除重复的 Electron RunPage。

02 · 产品边界

  • Dashboard 是唯一的主界面及日志投影后端；浏览器与 Electron 使用同一 URL、同一数据契约、同一状态模型。
  • Electron 负责窗口、托盘、Pet 浮窗、音频与本地偏好，通过小型 preload 能力接口接入共享页面。
  • 浏览器能完整使用运行与性能页面；Alice 设置明确说明需要桌面连接，不提供无效开关。
  • 不重写 Harness、Baseware 或日志协议，不引入第二套日志解析服务，不改变游戏会话、模型或控制策略。
  • 本次“Benchmark”覆盖已记录运行的性能观测；固定测试用例、任务分数、自动实验调度与跨版本结论不在本期。未知值显示“—”，不能补假数据。

03 · 信息架构与核心任务

位置用户任务内容和行为
固定侧栏知道自己正在看谁Playness 标识、当前 workspace、运行 / Benchmark / Alice 三个入口、可选 workspace 列表、连接状态。小窗口折叠为紧凑导航。
共享上下文栏切换运行但不丢位置workspace 名、run、epoch 选择；跟随最新或历史回放；刷新开关。URL 持有 project/run/epoch/view/block，前进后退恢复选择。
运行看画面与行动，读完整日志状态、当前阶段与已等待时长；模型输入画面为主，活动流为辅。thinking/text/tool/system 默认显示，diagnostic 按需启用。搜索及类型筛选、长内容展开、请求/来源信息和截图联动。
Benchmark判断慢在哪、有没有异常完成请求、动作、耗时中位数/p95、缓存、失败；请求耗时/缓存/请求体图；请求选择后联动原有工具/skill/错误/压缩证据与画面。来源计数和 Shiori→能力→设备显式调用关系单列，避免包含耗时与用量相加。
Alice调整陪伴方式桌宠显示、气泡/窗口通知、内容可见性、暂停展示、点击音量、导入/预览/重置音效。保留原生实现与本地偏好，不复制一套设置状态；尺寸继续通过托盘菜单调整。

04 · 关键交互

  1. 从浏览器 URL 或 Electron 启动指定 workspace；无显式选择时跟随最新 run/epoch。历史选择保持不变，实时刷新不把人拉回最新请求。
  2. 桌宠“详情”打开已有 Electron 主窗口，定位产生该气泡的 run/epoch/block；关闭窗口只隐藏窗口，Pet 继续工作。
  3. 切换 workspace/run/epoch 时清除原请求和截图选择，禁止展示其他周期的旧结果。正在读取显示加载态，读取失败标注错误与上次更新时间。
  4. 用户可暂停界面刷新，或暂停气泡展示；两者都不停止 Agent。交还控制权是独立显式按钮，保留后端 runId/epoch 原子校验；浏览历史时禁用并说明。
  5. 无 workspace、无接管周期、无请求、无图像、旧日志无 span、Host 离线分别有具体空态；不无限显示“加载”。
  6. 长日志可展开、滚动和复制；筛选影响显示，不改变后台日志或游戏行为。流式更新保持块身份和展开状态。
  7. 浏览器与 Electron 共享完整前端；只对真实可用的桌面能力显示可操作控件。外链经受限桌面处理，页面不获得任意 Node/文件执行能力。

05 · 视觉方向

采用安静、温暖的深色工作台：石墨灰主背景、略亮侧栏、暖白文字、Alice 发色呼应的低饱和金色重点；思考用淡紫、完成用鼠尾草绿、失败用珊瑚红，并始终辅以文字。避免霓虹、玻璃大渐变和密集嵌套卡片。游戏画面与日志是主角，仪表盘有信息密度但正文不低于 13–14px。

项目约定
画布1440×960 桌面设计目标；约 208px 侧栏，64px 顶栏；内容横向 28px 间距。运行页画面与日志约 58/42；窄窗口改为上下布局。
颜色背景 #171918；面板 #202321；侧栏 #1C1F1D；边线 #343A35；正文 #E9E9E2；次要 #A3AAA2；强调 #DBBC81。
排版系统 sans 中文字体，标题 26–30px，正文 14px，数据等宽。顶部短标题和一个说明，不用营销式大字占据首屏。
图表细网格、少量刻度、明确单位；点击可选请求，键盘亦可从列表选择。缺失值不画成 0 或穿越空值连线。颜色不作为唯一提示。
响应式1440/1280 完整布局；900 左栏收窄、内容叠放；390 导航横排，表格局部滚动，页面不横向溢出。交互焦点清晰，尊重减少动态效果。

06 · 数据与工程决策

保留现有 /api/catalog、/api/run、/api/activity、/api/media 和受保护的 /api/control。原统计口径保持；新增显式 spans/source 数据投影。Shiori usage 与现有模型 usage 不相加，能力成功不等于游戏推进，桌宠展示提交不等于完成绘制。

共享主 UI 放在 rsa-dashboard。Electron 主窗口加载配置好的本地 Dashboard；原 Pet renderer 与资源留在 rsa-companion。桌面专用设置逻辑复用现有 preload 和状态，由共享页面消费。只绑定本地源，Electron 保留 contextIsolation、禁用 Node integration，校验 IPC 的 webContents 与 frame 来源。

不为改版引入新的后端服务、数据库、通用插件框架或全套设计组件库。可拆出共享页面组件与纯投影函数；保留已有控制边界。

07 · 视觉稿

生成两张高保真主稿：运行页和 Benchmark 页。稿中 Besiege 场景与数字仅用于设计演示；实现使用真实日志，不把示例内容带入产品。

08 · 验收标准

  1. 浏览器与 Electron 展示同一个 Dashboard 页面，旧 Electron 运行页不再被构建或使用。
  2. 原有请求/动作/观测/技能/错误/压缩回放功能保留；新来源、span 信息在有证据时可见，旧日志显示缺失而非推断。
  3. workspace/run/epoch、页面和气泡 block 可深链接；历史选择与浏览器返回正常，跨周期不串数据。
  4. 真实日志可浏览；离线 fixture 可覆盖活动流、错误、空态、断连和历史周期。测试不产生游戏输入或在线模型请求。
  5. Alice 的原浮窗、图片、音频路径保持；声音导入/预览/重置、通知可见性可操作，尺寸保留原托盘入口。网页模式有明确能力边界。
  6. 1440 与 390 视口截图核对视觉稿，最小 900 宽桌面窗口可用，无页面横向溢出；按钮无死链接。
  7. 相关测试、类型检查和生产构建通过；代码与小型 PRD 进 Git，运行日志和原始大图留在 artifacts。

09 · 实现记录

已实现：rsa-dashboard 是唯一主 UI，提供运行 / Benchmark / Alice 三页；Electron 加载同一个本地页面，保留原生 Pet、托盘、音频与偏好。删除旧 React / Vite 主窗口及其依赖，Pet renderer 和资源保留。

  • 活动流默认展示思考、文本、工具与系统块，支持筛选、搜索、展开和精确 block 定位；历史 URL 固定 run/epoch，浏览器返回可恢复。
  • 调用链只连接显式身份；旧日志不推测 span。Shiori 与模型用量不重复累计，缺失指标显示“—”。
  • Dashboard 类型检查、53 项测试与生产构建通过；桌面类型检查、75 项测试与构建通过。
  • 浏览器实际验收：1440、900、390 宽度无页面横向溢出；真实 Besiege 日志、工具详情、页面切换、历史返回、网页 Alice 设置不可用说明均已核对，无浏览器控制台错误。
  • 真实 Electron 临时 profile 烟测通过：HTTP 页面加载生产 preload，渲染进程无 Node；声音和偏好 IPC 可用，Pet 详情保留 run/epoch/block，异源 IPC 被拒绝。未重启现有 Pet、宿主或游戏，未发在线模型请求。

生成稿与验收截图保存在仓库外的 artifacts/unified-console-design，避免将大图与运行画面带入源码仓库；clone 本仓库不会包含这些本机附件。验证范围不包含一次新的真实游戏运行，原有日志缺少 telemetry 的字段仍显示缺失。
